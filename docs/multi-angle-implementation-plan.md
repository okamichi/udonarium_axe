# 多方向閲覧の実装計画

利用方法と現在の画面仕様は、[2D 多方向閲覧と外周ティッカー](multi-angle.md)を参照。

## 目的

`multi-angle.md` に記載された別ソフト向けの仕様を、ユドナリウムアックスの2Dモードへ移植する。画面を水平に置き、上下左右の四方から囲んだときに、参加者全員がコマの情報を同時に読める状態を目指す。

既存の盤面は Canvas ではなく、Angular コンポーネントと DOM/CSS 3D 変換で構成されている。そのため、参照仕様の描画関数を移すのではなく、角度・配置・アニメーションの規約だけを純粋関数として移植し、各表示コンポーネントへ段階的に適用する。

## 実現方針

- 機能はテーブルの `mode2d` が有効な場合だけ動作させる。
- 既存ルームの見え方を変えないよう、多方向表示は初期状態で無効にする。
- 卓を囲む全員が同じ表示を見る用途なので、設定は `GameTable` の同期プロパティとして保持する。
- 回転ラベルは「キャラクター名/バフ名の先頭5文字」を基本形とし、各文字をSVG円周の接線方向へ曲げて表示する。
- 短いラベルは4方向へ等間隔に4個配置し、円周長に収まらなければ3個、2個、1個へ自動的に減らす。
- 複数ラベルの中点には `◆` と全角相当の余白を置き、`名前/状態 ◆ 名前/状態` と区切って読めるようにする。
- 曲線になったラベル群全体を時計回りに周回させる。
- コマ画像と台座だけを、名前とは別の速度でゆっくり時計回りに回転させる。
- HP/MPバー、バフ・状態アイコン、増減値、ターゲット表示などの情報オーバーレイは回転させない。
- コマID由来の決定的な位相を与え、全コマの開始角をばらしつつ、全参加者には同じ角度を表示する。
- 周回はコマと同じ盤面上の `rotateZ(0deg)` から `rotateZ(360deg)` だけで構成し、途中で `rotateY` に置き換えない。
- 角度規約は時計回りに下 0°、左 90°、上 180°、右 270°とする。
- 幾何計算と時計は `domain/tabletop` の純粋関数に置き、DOM 変換は既存の `ui/tabletop/billboard-transform` に寄せる。
- `requestAnimationFrame` が必要な機能は盤面単位の1ループへまとめる。コマごとにタイマーを作らない。
- 卓の手動回転には既存の `GameTableGestureService.viewRotateZ` と `UiSignalService.tableViewRotation` を利用し、入力座標変換は既存の CSS 行列ベースの処理を維持する。

## 参照仕様からの対応表

| 参照仕様                   | ユドナリウムアックスでの実装先                                   |
| -------------------------- | ---------------------------------------------------------------- |
| `SEATS`、`seatVec`、`comp` | `domain/tabletop/multi-angle.ts` の純粋関数                      |
| `drawText4`                | ラベルを最大4個、円周長に応じた個数で等間隔に生成する            |
| `spinClock`、位相ばらし    | CSS の盤面Z軸アニメーションとコマ ID の決定的ハッシュ            |
| 円周文字                   | 各ラベルを SVG `textPath` へ置き、文字ごとに円の接線へ沿わせる   |
| 外周ティッカー             | 専用チャットタブの投稿を読む `game-table` の画面座標オーバーレイ |
| 卓回転補正                 | 既存のビルボード変換と `viewRotateZ` に席角度を合成              |
| 挿絵ウィンドウ             | `game-table` の外側に置く画面座標オーバーレイ                    |

## 実装段階

### 第1段階: 角度規約とコマ名の時計回り周回

1. 四席の定義、角度正規化、席ベクトル、卓回転補正を純粋関数として追加する。
2. `GameTable` に opt-in の同期設定 `multiAngleEnabled` を追加する。
3. テーブル設定画面で、2Dモード時だけ多方向表示を有効化できるようにする。
4. キャラクター名とバフ先頭文字を組み合わせ、長さに応じて1〜4個をSVG円周へ等間隔に置く。
5. 各文字を曲げた状態で盤面のZ軸上を時計回りに周回させる。
6. コマ本体を独立した速度と決定的な開始位相で回転させる。
7. 2Dモード以外と、設定が無効な場合の DOM と変換を従来どおりに保つ。

この段階を最初の縦切りとする。設定、同期モデル、座標計算、実表示を一度に通すことで、後続機能の土台が正しいかを早期に確認できる。

### 第2段階: コマ情報全体への適用

- 数値ゲージと一時的な増減表示を多方向閲覧へ対応させる。
- 状態異常は名前と衝突しない周回レーンまたは固定表示に整理する。
- 6 と 9 を含む数字だけの表示には上下判別用の下線を付ける。
- 画像と文字を分離し、画像は指定した1席だけに向ける。
- 盤面文字倍率を追加し、離れた席から読める大きさへ調整できるようにする。

### 第3段階: 回転速度・間欠回転（第1段階へ前倒し）

- 表示方式を「時計回りの連続回転」「90°回転して静止」から選べるようにする。
- 名前が回転だけで一周する秒数と、90°ごとの静止秒数を同期設定として保持する。
- コマ本体が一周する秒数は名前とは別の同期設定として保持する。
- CSS の1本の回転キーフレームへ動的な `linear()` イージングを与え、間欠モードでは各90°を滑らかに回した後に静止する。
- JavaScript のコマ別タイマーは作らず、ブラウザのCSSアニメーションへ処理をまとめる。

### 第4段階: 長文と挿絵

- キャラクター詳細、チャット、チャットパレット、インベントリなどが共有するウィンドウ枠へ、時計回りの90°回転ボタンを追加する。
- 回転はウィンドウごとに `0/90/180/270°` を保持し、移動・縮小・全画面・閉じる操作をそのまま利用できるようにする。90/270°の全画面表示では縦横寸法を入れ替え、回転後の外接矩形を画面内へ補正する。
- 回転中のリサイズ入力はポインター移動量をウィンドウのローカル座標へ逆変換し、画面上の向きに合う辺を操作できるようにする。
- 固定識別子を持つティッカー専用の同期チャットタブを用意する。通常のチャット送信、履歴、閲覧・発言権限を再利用し、そのタブへの投稿だけをティッカーの入力として扱う。タブ内に表示ON/OFFと速度スライダーを置く。
- 画面の上下左右に、その席から正位置で読める小さなランチャーボタンを置く。ボタンを押すと、押した席の向きでティッカー投稿・表示設定パネルを開く。入口だけを4か所に複製し、操作パネルは同時に1枚だけ表示する。
- 専用タブの最新投稿を受け取ったら、発言者名と本文を画面四辺へすぐに反映する。同じ投稿を各クライアントで重複起動しないよう、メッセージ ID を処理済みキーに使う。新着がなければ最後の投稿を繰り返す。
- 短い投稿は `◆` 区切りのコピーを最大8個まで外周へ等間隔に並べ、四辺に大きな空白が残らないようにする。長い投稿ではコピー同士が詰まらない個数まで自動的に減らす。
- 正方向の経路は下0°・右270°・上180°・左90°として文字の上を画面内側へ向け、移動量だけを負方向へ進める。これにより下辺は右から左、左辺は下から上、上辺は左から右、右辺は上から下へ連続して一周する。
- テーブル設定にはティッカーの表示 ON/OFF、速度、方向、文字サイズと、使用する専用タブの識別子を保持する。チャット履歴そのものをテーブルへ重複保存しない。
- 文字サイズに応じて余白と周長を再計算し、逆回転時も正の剰余で位置を正規化する。
- 秘話、ダイス結果、システムメッセージを流すかは明示的に選別する。初期実装では全体公開の通常発言だけを対象にする。
- 挿絵を4分割表示または90°時間回転で表示する画面座標オーバーレイを追加する。
- 画像取り込み時に上限解像度へ縮小し、保存データの肥大化を防ぐ。

### 第5段階: 卓回転と対象拡張

- 必要なら卓の90°スナップと自動回転を追加する。
- コマ、ダイス、カード、テキストノートのうち、四方向表示が有効な情報を整理して適用する。
- 壁面上のオブジェクトとポスター表示は対象外のままにし、床面の2D表示だけに限定する。

## 検証方針

- 純粋関数: 4席の角度・ベクトル、0/90/180/270°の卓回転補正、回転時計、決定的位相を Vitest で検証する。
- DOM: 設定 OFF では従来名札が1個、ONでは長さに応じた1〜4個の `textPath`、名前周回クラス、コマ本体回転クラスが付くことを確認する。
- 時計: 連続回転の一周秒数、90°回転・静止を表す `linear()` の停止点、ID由来の決定的位相を純粋関数テストで確認する。
- 回帰: 3Dモード、ポスター、コマの移動・選択・回転、グリッド表示、視界処理に変化がないことを確認する。
- 統合: `npm test`、`npx vitest run`、`npm run lint`、`npm run build` を通す。
- 実機: 横置き画面を四方から確認し、名前の重なり、読みやすさ、タッチ操作の当たり判定を調整する。
- ローカル単独確認: `http://localhost:4200/?local=1` で開き、SkyWayへ接続せずに盤面表示を確認する。

## 主なリスク

- 既存のコマ装飾は複数階層の CSS 3D 変換を使うため、変換を置く階層を誤ると席角度と配置角度が一致しない。席別の移動は外側、文字の回転はビルボード補正後の画面座標で適用する。
- 周回する名札は近接したコマと重なりうる。第1段階ではコマサイズ連動の半径と省略表示を使い、実機確認後に速度と間隔を調整する。
- 四辺のランチャーは既存のフローティング UI やモバイル表示と競合しうる。安全領域を設け、通常のオンライン利用では非表示にする。
- 同期設定を増やすと古い保存データに値がない。クラスの初期値を常に安全側の `false` とし、既存データでは機能を無効にする。
- 常時アニメーションは端末負荷を増やす。JavaScriptタイマーを増やさずCSSアニメーションへ集約し、設定OFF時はアニメーションクラスを付けない。
